# 数据库与业务规则

## 关键关系

`Merchant → User / Partner / Location / Good / Loan / Sale / Receipt / Payable / Payment`。每张业务表包含 `merchantId`，接口查询和写入均限定商家。`Partner.roles` 允许一人多种合作身份，停用档案不应删除历史单据。

`Good` 一行对应一件实物，有商家内唯一货号。`ownershipKind` 和 `ownerPartnerId` 保留原采购或寄售来源；`currentOwnerKind/currentOwnerPartnerId` 表示当前货权。`holderKind/holderPartnerId`、`locationId` 和 `custodianUserId` 分别表示持有、物理位置及保管责任。`quality` 和 `occupancy` 各自独立，避免把货损、借出和成交混成单一状态。每次状态改变都在同一数据库事务写入 `InventoryEvent` 的前后快照。

`Loan → LoanItem → Good` 逐件保存拿货和归还。`Sale → SaleItem → Good` 逐件保存成交、优惠、退款、交付；`Payable` 对应寄售销售明细。`Receipt`、`Payment` 是实际资金收付，核销明细分别记录到销售明细或期初余额。押金和预付款保留在独立收款类别。`MoneyEntry` 登记期初余额、实际退款、待退款以及已付上游后的待追回或抵扣款。

## 金额与结算

数据库金额用 `BigInt` 整数分，接口输出元的两位小数字符串；输入也要求元的十进制字符串。重量用 `Decimal(12,3)`。比例用万分比整数，逐件以四舍五入到分计算；整单优惠按各件原价比例分摊，尾差给固定顺序的最后一件。

寄售货成交立即生成应付：固定价使用录货时的固定金额；比例分成按逐件优惠后的成交净额乘万分比。规则与版本在货品和应付记录中留快照。客户款收齐后才允许该件货的上游付款。客户应收、上游应付不自动相抵。

试用货权规则为“成交且交付后转给客户”。未交付的成交货保持原货权但不再可售。此规则尚待摊主正式确认；原货主及来源记录不因转移而覆盖。

## 纠错与限制

数据库对商家内货号、外部编号及有效借货、有效销售设置唯一约束；借出和销售锁定货品行，在事务中同步更新单据与流水。员工权限在服务端校验。收款与付款可分次、跨单核销。已付上游后发生退货，原付款不改写，产生待处理差额；老板明确登记上游实退现金或抵后续应付。货损未确认责任前不产生扣款。

盘点只纳入指定位置中商家实际持有的货；外借货不自动记盘亏。盘点期间变动的货品要求重新核对，缺货先标待处理。
