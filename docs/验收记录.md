# 第一版验收记录

验收日期：2026-09-26。所有验证使用演示库、独立 `feicui_test` 测试库或独立恢复库；未录入真实客户或交易。`./scripts/test.ps1` 的 13 项业务测试、13 项小程序接入测试、3 项文件解析测试及 2 项标签版式测试通过；`node scripts/smoke.mjs` 对生产启动后的实际 HTTP 接口通过，`node scripts/mini-smoke.mjs` 验证小程序凭证、同库至少 50 件演示货、员工成本隔离和未授权拒绝。`node scripts/import-preview-smoke.mjs` 使用真实 CSV 和 XLSX 文件通过 HTTP 导入预览；`node scripts/stocktake-smoke.mjs` 通过实际 HTTP 验证错位货移入、未登记货号留痕和复核结案。 `node scripts/damage-smoke.mjs` 通过实际 HTTP 验证员工越权拒绝、继续待处理、老板修复放行且无自动扣款。`npm run build` 完成，TypeScript 校验通过。桌面与 390 像素手机视口已检查首页和货品页，手机首页操作区的窄按钮问题已修复。

补充检查：合作方结算规则由第 1 版改为第 2 版后，旧货成交仍按第 1 版结算；两件货的整单优惠先分摊到逐件净额，再分别计算比例应付。

盘点补充：盘点期间货品被预留或移出货位时，结束盘点先被阻止；逐件重新核实后可结束，移出货不被误记为盘亏。扫码发现快照外多货、错位或未登记货号时形成持久差异；待复核差异阻止结束盘点。复核移入货位后库存位置、盘点明细与流水在同一事务更新，复核忽略保留说明。网页与小程序均要求复核人填写说明，并按权限提供扫码、差异处置和结束入口。

异常货补充：拿货归还、销售退货及盘点未见可形成异常记录。独立数据库测试验证老板记录责任与照片、继续待处理、修复放行、确认报损及重复结案拒绝；员工不能结案，货损处置不自动产生扣款。小程序提交同一处置接口。

浏览器补充：在演示库生成一件待处理异常货，网页“货品 → 异常货与货损”显示责任、处置和凭证选项；老板在页面选择“本摊”“已修复，恢复可售”并提交说明后，页面显示复核成功、待处理数量从 1 降为 0，货品恢复可用。留有 [货损复核截图](./浏览器验收-货损复核.png)。

导入补充：上传解析已改用 `read-excel-file` 和 `csv-parse`，不再使用存在公开高危漏洞的旧版 `xlsx` 包。CSV 要求 UTF-8；超出行列上限、重复或危险表头会被拒绝。`npm audit` 仍报告 Prisma CLI 的开发依赖链存在安全公告，运行时导入不依赖该链；正式部署前应关注 Prisma 上游修复并重新审计。

备份恢复：早期备份 `backups/20260926-015056` 曾恢复到独立数据库，货品 62 件、图片 5 张。新增盘点与异常货流程后，再次生成 `backups/20260926-233312`，恢复到独立数据库 `feicui_restore_20260926233329`；货品 66 件、图片 5 张，28 张业务表数量逐表一致，图片文件逐一通过 SHA-256 对比，未覆盖演示库。新增演示货来自可重复执行的 HTTP 与浏览器验收。

## 仍需现场确认或扩展

- 货权在“确认成交且交付后转给买家”是**试用配置**；老板正式使用前须确认。上游分账比例、押金用途及历史期初金额也须按真实协议核对。
- 网页实时摄像头扫码已接入查货、拿货、成交、盘点，使用 ZXing，仍保留扫码枪和手工输入。小程序使用微信 `wx.scanCode`，支持扫描新货号后入库；自动化验证扫描号创建一件货和入库流水、重复号拒绝。本机 `127.0.0.1` 属于可请求摄像头的安全上下文；局域网手机访问网页须配置 HTTPS。真机扫码的摄像头许可与设备效果尚待现场验收。
- 浏览器已检查桌面和手机首页、货品查询及快速录货；另在演示库通过桌面浏览器完成一笔 88 元货品成交、50 元实际收款及逐件核销、实物退货并退回 50 元，页面显示未收从 88 元变为 38 元再归零，货品恢复可用。留有 [验收截图](./浏览器验收-成交退款.png)。其他复杂页面分支仍以真实 PostgreSQL 测试和 HTTP 验收为主，未逐按钮覆盖。
