# 与飞彪珠宝服务平台的对标分析

对标对象：飞彪珠宝服务平台（feibiao.cn / fbzs.net），翡翠 ERP 行业市占率第一，官方口径 9000+ 商户、累计处理订单 52 亿次。
对标者：本项目「翠账」，面向单个翡翠摊主的本地管货与对账系统。

日期：2026-09-27

## 一、先看清定位差异

飞彪不是一个软件，而是"三款产品 + 一条硬件/生态链"：

| 飞彪产品 | 业态 | 主场景 |
|---|---|---|
| 直播间供应链一体化管理 | 直播间、供应链、供货中心 | 多平台订单、配货售后、借还货、货主分账 |
| 原石供应链管理 | 原石/毛料、档口、加工 | 原石入库、毛料借还、图集核对、加工流转 |
| 金管家 | 黄金珠宝门店 | 金价同步、旧料、多门店调拨、会员赠品 |

翠账只做第一、二条里"单个摊位/小档口"的那一段：一件货从进来、被谁拿走、到什么状态、卖了多少钱、该给上游多少、收了多少钱。

所以差距要分两类：**功能差距**（同赛道但你没做）和**生态差距**（平台白名单、RFID 硬件、多租户 SaaS —— 属于商业资源，不是代码问题）。后者不要在代码层面硬追。

## 二、你已经做对、甚至更强的部分

这些是飞彪宣传口径里没有强调、但在账目纠纷时最值钱的东西。不要为了对齐而简化掉。

| 能力 | 本项目实现 | 说明 |
|---|---|---|
| 四维分离 | `ownershipKind` / `currentOwnerKind` / `holderKind` / `locationId` / `custodianUserId` | 货权、当前货权归属、谁持有、在哪、谁负责保管各自独立 |
| 品质与占用双轨 | `quality` + `occupancy` | 不把货损、借出、成交混成一个状态 |
| 三分离确认 | `Sale` / `deliveryStatus` / `paidCents` | 成交 ≠ 交付 ≠ 收款，三条线分别走到才确认 |
| 寄售资金闸门 | 客户款收齐才允许付上游 | 避免自己垫付后收不回来的风险 |
| 已付后退款不改写 | `MoneyEntry` 的 `SUPPLIER_REFUND` 等 | 原付款留痕，产生待处理差额由老板明确登记 |
| 结算规则快照 | `Payable.ruleSnapshot` + `ruleVersion` | 事后改价不污染历史应付，可追溯 |
| 逐件过错 leaning | `InventoryEvent` 前后快照 + `AuditLog` + `version` 乐观锁 | 每次状态变化全自动留痕 |
| 盘点闭环 | 5 种差异类型 + `disposition` + 老板复核说明 | 飞彪是"自动生成调整单"，你这边差异必须有人认领 |
| 成本隔离 | `staff` 不可查看成本及账务 | 等价于飞彪的"暗码设置" |
| 数据自持 | PostgreSQL 本地/自部署 + 备份 + 恢复验证脚本 | 飞彪是 SaaS，数据在他那边 |

结论：**在账务严谨性这条线上，你不比飞彪弱，某些点更强。** 这是本项目相对通用 ERP 的真实壁垒，对标时应当保留并作为卖点讲。

## 三、真实功能差距（值得补）

按"能不能用手上已有骨架低成本补齐"排序。

| # | 差距 | 现状 | 骨架复用程度 |
|---|---|---|---|
| 1 | 借入方向缺失 | 只有 `Loan`（借出给客户/代卖）；寄售靠 `ownershipKind=CONSIGN` 表达，没有独立借入单与应还期限 | 低。需要反方向的单据模型 |
| 2 | 逾期被动 | 首页有"到期事项"列表，但无主动提醒通道 | 低，小程序订阅消息可补 |
| 3 | 无经营报表 | 只有 `GET /dashboard` 计数，没有毛利、应收账龄、客户销售排行、滞销分析 | 中，数据齐全只缺聚合查询 |
| 4 | 无对外货盘 | 只有 `ShareLink` 的只读对账单 | 高。token/PIN/过期/撤销已就位，加可售筛选与图片墙即可 |
| 5 | 分账不闭合 | 无主播/介绍人佣金角色，无结算单与凭证导出 | 中高，`Payable` 已有 70% 骨架 |
| 6 | 采购无批次 | 入库靠逐件手工录货，整批拿货时录入很慢 | 低，`ImportBatch` 只能做，但没有采购单概念 |
| 7 | 售后不闭环 | 有退货和货损，但没有换货、没有退货通知货主 | 中 |
| 8 | 无图片检索 | 无拍图找货、丢标识别 | 低起步：可以按图相似度做轻量版 |
| 9 | 无主动找货能力 | 只能按货号/名称查 | 低，与 8 合并做 |

## 四、定位不同，明确不做

飞彪这些能力依赖直播平台官方授权、行业白名单或硬件，或属于别的业态。翠账第一版边界里已经排除过一次，继续保持。

- 多平台订单同步（抖音/快手/视频号/淘宝/拼多多/小红书/百度）——需要平台 API 白名单
- QIC 基地质检发货、快递物流面单
- RFID 盘点设备、通道门、声光防盗
- 金价实时同步、旧料管理、多门店调拨、会员积分赠品（金管家线）
- 原石入库、毛料借还、图集核对、加工流转（原石线）
- 在线支付收单
- 多租户 SaaS 计费与客服体系

## 五、补齐优先级建议

### P0 —— 补齐后可自称"档口版飞彪"

1. **借入/借出的双向单据**：`Loan` 增加 `direction`（OUTBOUND/INBOUND），支持从货主处借入、`dueAt` 应还日、批量还货。
2. **经营报表**：毛利、应收账龄、寄售未结、客户出货排行、滞销库存（>N 天未动）。
3. **对外货盘（飞彪相册替代）**：复用 `ShareLink`，生成只读货盘页 —— 图片墙 + 可售筛选 + 隐藏成本/底价 + 一键询价/预留。
4. **逾期提醒**：到期未还、逾期未收、押货超期，经微信小程序订阅消息推送。

### P1 —— 增强留存

5. **采购单与批量入库**：一张采购单录入多条明细，自动按规则生成货号与条码，支持打印整批标签。
6. **结算单与凭证导出**：按合作方生成可 PDF/图片导出的结算单，含期间明细、已付未付、结算规则条款。
7. **佣金分成**：在 `Partner` 上支持"介绍人/主播"角色并在 `Sale` 上挂佣金，结算时同表计算。
8. **售后换货与退货通知**：以货换货流程，退货后自动通知货主。

### P2 —— 差异化

9. **以图搜货**：按图片相似度做"拍图找货 / 丢标识别"，不用依赖大模型 API 也能起版。
10. **收支流水核对**：导入微信/支付宝账单 CSV 与系统收款记录自动对账。
11. **PDA 模式**：小程序里做一个大按钮、大字号、连扫模式的极简界面，用于仓库批量扫码。

## 六、一句话结论

对标飞彪不该理解为"把它的功能抄一遍"，而是：**守住账务严谨性的领先点，补齐向外（货盘/报表/提醒）和向内（借入/采购/结算单）的四个断口。** 生态类能力（平台 API、RFID、金价）留在边界外，避免把成本砸在拿不到资源的地方。
